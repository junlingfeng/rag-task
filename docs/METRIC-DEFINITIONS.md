# 指标口径定义与评测方法
> English version: [METRIC-DEFINITIONS.en.md](METRIC-DEFINITIONS.en.md)


文档要求 "define your evaluation method"，因此下列定义本身就是交付物的一部分。每一项都给出：阈值、定义、公式、实现方式、数据需求、注意事项。

## 0. 评测数据集设计（所有指标的前置条件）

这是整个交付里工作量最大的部分，必须先做。

| 子集 | 规模建议 | 内容 | 支撑的指标 |
|---|---|---|---|
| 单轮可答集 | ≥ 100 题 | 问题、标准答案、标准证据 chunk id | Context Precision、Faithfulness、Compliance、Style |
| 多轮对话集 | ≥ 20 组会话 | 每组 3–5 轮，含指代与省略 | Context Precision、Compliance |
| 越界集 | ≥ 30 题 | 语料中无答案的问题 | Refusal Appropriateness |
| 不安全集 | ≥ 20 题 | 注入、越权、违规请求 | Refusal Appropriateness、注入防御 |
| 低置信度集 | ≥ 20 题 | 语义相近但无确切依据的问题 | Refusal Appropriateness |
| 中文 / 英文 / 混排 | 均衡覆盖 | 覆盖双语需求 | 全部指标 |

标注要求：

- 证据片段必须标注到 chunk 粒度，并与线上真实切分策略一致（切分策略变更后需重新标注或建立映射）。
- 标准答案用于 judge 参考，不作为唯一正确答案（避免答案多样性被误判为错误）。
- 数据集固定并纳入版本管理，调参过程中禁止改动，否则前后对比失效。

## 1. RAG 指标

### 1.1 Faithfulness（目标 ≥ 0.85）

**定义**：答案中的原子断言有多少比例能被检索到的上下文支持。

**公式**：

```
Faithfulness = 被上下文支持的断言数 / 答案中的断言总数
```

**实现**：

1. 用 judge 模型把答案拆解为原子断言列表（每条只含一个事实）。
2. 对每条断言判断是否被检索上下文蕴含（entailed / contradicted / not-mentioned 三分类）。
3. 统计 entailed 占比。

**注意**：拒答不计入分母；拒答质量由 Refusal Appropriateness 单独衡量。

### 1.2 Context Precision（目标 ≥ 0.70）

**定义**：检索结果中真正相关的片段占比，并按排名加权（越靠前权重越高）。

**公式**（rank-weighted）：

```
ContextPrecision@k = Σ_{i=1..k} ( Precision@i × rel(i) ) / 相关片段总数
Precision@i        = 前 i 个片段中相关片段数 / i
rel(i) ∈ {0,1}
```

**实现**：以标注的证据 chunk id 为 ground truth，判断检索结果是否命中。

**注意**：

- 固定 `k`（建议与线上传给生成模型的 top_n 一致），并额外报告 k=5/10/20 的曲线。
- 跨语言检索时，中文问题命中英文片段应记为相关。
- 多轮会话中，改写后的问题用于检索，指标评价改写链路的最终效果。

## 2. 生成质量指标

### 2.1 Answer Compliance（及格 ≥ 80%，进阶 ≥ 90%）

**定义**：答案满足全部合规检查项的通过率。

**检查项（逐条 0/1，全部满足才计通过）**：

| 检查项 | 说明 |
|---|---|
| 有据可依 | 答案中的事实均可在检索上下文中找到依据 |
| 引用完整 | 给出来源引用（文档 id / 章节） |
| 直接回应 | 回答了用户实际问题，未偏题 |
| 格式合规 | 满足约定的回答结构 |
| 无编造 | 无上下文之外的事实、数字、条款 |
| 无禁止内容 | 不含 PII、内部敏感标识、越权承诺 |

**公式**：`Compliance = 全部检查项通过的答案数 / 计分答案总数`

**实现**：LLM-as-judge 按评分表输出逐项判定与总分；另抽 ≥ 20% 样本人工复核，报告一致率。

### 2.2 Style Consistency（及格 ≥ 80%，进阶 ≥ 0.85）

**定义**：答案在语言、结构、语气三个维度与规范的一致程度，取平均分。

| 维度 | 评分规则 |
|---|---|
| 语言一致性 | 中文问题答中文、英文问题答英文、混排问题按主语言；完全一致 = 1，部分 = 0.5，不符 = 0 |
| 结构一致性 | 遵循统一回答模板（结论 → 依据 → 引用） |
| 语气一致性 | 客观、简洁，无营销化表达与口语化冗余 |

**公式**：`StyleConsistency = mean(语言分, 结构分, 语气分)`，范围 0–1。

**注意**：报告中同时给出百分比表达（0.85 = 85%），避免与 80% 阈值混淆。

### 2.3 Refusal Appropriateness（及格 ≥ 80%，进阶 ≥ 90%）

**定义**：系统"该拒则拒、不该拒则不拒"的双向准确率。**单向统计会被"全部拒答"策略刷满，必须双向。**

**公式**：

```
正确拒答率 = 应拒答且已拒答数 / 应拒答总数
正确应答率 = 应应答且已应答数 / 应应答总数
RefusalAppropriateness = 2 × 正确拒答率 × 正确应答率 / (正确拒答率 + 正确应答率)   # 取 F1
```

**拒答触发条件（三条均需实现）**：

1. 置信度低：检索分数低于阈值，或 judge 判定上下文不足以支撑答案。
2. query 越界：语料中不存在相关证据（范围分类器 + 检索分数联合判定）。
3. 安全规则命中：prompt 注入、越权请求、违规内容。

**拒答输出要求**：不能只返回"无法回答"，必须给出**引导**（说明原因类别 + 建议的可行方向）。

## 3. 性能指标

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 端到端延迟 | 请求进入 → 完整响应返回（需显式声明是否流式） | 每请求打点 |
| P50 / P90 / P95 | 延迟分位数，P90 ≤ 10s 为硬约束 | 评测脚本与线上日志统计 |
| 分阶段耗时 | 改写 / 检索 / 重排 / 生成 / 后处理 各阶段耗时 | 阶段 span |
| 并发能力 | 单实例 ≥ 5 并发下 P90 仍 ≤ 10s | k6 / Locust 压测，注明硬件规格与请求分布 |

延迟预算建议（总预算 10s）：

| 阶段 | 预算 |
|---|---|
| 查询改写 | ≤ 0.5s |
| 检索（向量 + BM25 并行） | ≤ 0.5s |
| 重排 | ≤ 0.5s |
| 生成 | ≤ 7s（首要优化对象） |
| 后处理与网络 | ≤ 0.5s |
| 留白 | ≥ 1s |

## 4. 成本指标

**要求**：给出每 1000 次调用的 token 成本估算，并说明模型版本选型的质量/成本/延迟权衡。

**公式**：

```
CostPer1k = 1000 × (avg_prompt_tokens × P_in + avg_completion_tokens × P_out)
```

**实现**：

1. 逐请求记录 prompt / completion token 数（含 judge 与 embedding 调用，并在报告中区分"服务成本"与"评测成本"）。
2. 维护模型价格表（含缓存命中折扣，如有）。
3. 对候选模型（大模型 / 小模型 / 量化版本）在同一评测集上给出三方对照：质量、单次成本、P90 延迟。

**注意**：选型结论必须有数据支撑，例如"小模型质量低 6 个百分点，但成本降 80%、P90 降 60%"，再给出最终选择与理由。

## 5. 缓存指标

| 指标 | 定义 |
|---|---|
| Cache Hit Rate | 命中缓存的请求数 / 总请求数 |
| 缓存正确率 | 命中缓存且答案仍正确的比例（防止陈旧或错误命中） |

**要求**：缓存命中率必须进入运维报告；同时说明失效策略（TTL + 文档更新触发失效）。

## 6. 运维报告字段（FR4 强制）

| 字段 | 说明 |
|---|---|
| p50_latency_ms | 中位延迟 |
| p95_latency_ms | 95 分位延迟 |
| token_usage | prompt / completion / total，按模型分组 |
| cache_hit_rate | 缓存命中率 |
| refusal_rate | 拒答率（按原因分类：低置信度 / 越界 / 安全） |
| answer_compliance_rate | 答案合规率 |

输出格式：txt（人读）+ CSV（机读）双份。

## 7. Judge 设计规范

多个指标依赖 LLM-as-judge，必须规范化，否则指标不可信。

| 项目 | 要求 |
|---|---|
| 模型分离 | judge 模型与生成模型不同，避免自我偏好 |
| 结构化输出 | 固定 JSON schema，逐项判定 + 分数 + 理由 |
| 评分表 | 每个维度给出清晰锚点（0 / 0.5 / 1 的判定标准） |
| 温度 | judge 使用 temperature=0，固定随机种子 |
| 人工校准 | 抽取 ≥ 20% 样本人工复核，报告一致率（建议 ≥ 0.8） |
| 稳定性 | 同一输入重复评测结果一致，需报告自一致性 |
| 可审计 | 保存 judge 原始输出，便于抽查与复盘 |

## 8. 可复现性要求

- 固定随机种子与采样参数。
- 模型版本与 prompt 版本纳入配置，并随请求记录。
- 评测数据集与评测脚本版本化。
- 一键脚本在数据不变时应得到一致的指标与报告。
