# Log Field Dictionary and Sample Logs

> Chinese version: [LOG-FIELD-DICTIONARY.md](LOG-FIELD-DICTIONARY.md)

## 1. Field dictionary

| Field | Type | Description |
|---|---|---|
| `ts` | string | Event time (ISO8601, local timezone) |
| `level` | string | Log level |
| `event` | string | Event name: span or request |
| `trace_id` | string | End-to-end trace id |
| `request_id` | string | Single request id |
| `session_id` | string | Session id (multi-turn) |
| `turn_index` | int | Turn number within the session |
| `stage` | enum | rewrite / retrieve / rerank / guardrail / generate / postprocess / cache / total |
| `latency_ms` | number | Stage duration in milliseconds |
| `config_version` | string | Configuration version |
| `config_fingerprint` | string | Configuration fingerprint (content hash) |
| `prompt_version` | string | Prompt version |
| `corpus_version` | string | Knowledge-base version |
| `retrieval_mode` | enum | vector \| hybrid |
| `rerank_enabled` | bool | Whether reranking was enabled |
| `top_k` | int | Recall size |
| `top_n` | int | Evidence passed to generation |
| `retrieved_chunk_ids` | string[] | Chunk ids retrieved |
| `retrieval_scores` | number[] | Final fused scores |
| `vector_scores` | number[] | Vector-channel scores |
| `lexical_scores` | number[] | Lexical-channel scores |
| `rerank_scores` | number[] | Rerank scores |
| `rerank_timeout` | bool | Whether reranking timed out and degraded |
| `cache_hit` | bool | Whether the cache was hit |
| `cache_key_hash` | string | Cache key hash (no plaintext) |
| `prompt_tokens` | int | Input token count |
| `completion_tokens` | int | Output token count |
| `total_tokens` | int | Total token count |
| `cost_usd` | number | Estimated cost for this request (USD) |
| `model_id` | string | Generation model identifier |
| `answer_status` | enum | answered \| refused \| error |
| `refusal_reason` | enum | low_confidence \| out_of_scope \| safety \| no_evidence |
| `citation_ids` | string[] | Evidence chunk ids cited by the answer |
| `support_score` | number | Degree to which the answer is supported by evidence |
| `injection_flags` | string[] | Prompt-injection signatures matched |
| `pii_redacted_fields` | string[] | Fields that were redacted |
| `user_query` | string | The user question (redacted per configuration) |
| `error_type` | string | Exception type |

## 2. Log structure

Each request produces two kinds of record:

- `event=span`: instrumentation for a single stage (rewrite / cache / retrieve / guardrail / generate /
  postprocess). Each carries `trace_id` and `stage`, used to localise latency and stage behaviour.
- `event=request`: the summary record for one request. Every metric in the operations report comes
  from these records.

## 4. Redaction

`user_query` and the answer are PII-redacted before being written to disk (email, mobile number,
national ID, bank card, employee id, internal code). Matches are recorded in `pii_redacted_fields`.
Hash mode is the default, preserving traceability without writing plaintext.
