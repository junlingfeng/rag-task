## 2. Evaluation method

| Item | Description |
|---|---|
| Corpus | Self-built bilingual corpus covering employee handbook, compliance guide, technical spec and architecture document, including 2 image-only scanned files |
| OCR | RapidOCR on scans rendered at 300 DPI; measured confidence ≈ 0.98 |
| Chunking | Structure-aware recursive chunking with parent-child blocks (child 320 tokens, parent 1300 tokens) |
| Embeddings | ONNX multilingual model (MiniLM-L12 int8, 384-dim, no PyTorch required) |
| Reranking | bge-reranker-base (ONNX int8 cross-encoder), 10 candidates / 800 ms timeout fallback |
| Generation | OpenAI-compatible endpoint (DeepSeek in this evaluation) |
| Judging | LLM judge, batched with automatic binary retry on failure; refusals scored from objective status |
| Labelling | Facts carry unique anchors; gold chunks are recovered after chunking; cross-language anchor fallback supported |
| Caching | Disabled during evaluation — cache hits would skip retrieval and mask real retrieval quality |
| Multi-turn rewriting | Triggered only when the question depends on context (anaphora / topic-less follow-up) |

> not optimised in isolation.

## 5. Issue diagnosis and before/after

Controlled experiments (one variable changed at a time, each with before/after data) are in
`reports/diagnosis_report.md`; summary:

| Issue | Before fix | After fix | Improvement |
|---|---|---|---|
| Chunk granularity too small (120 → 320 tokens) | Low Recall@5 | See diagnosis report | ≥ 10% |
| Out-of-scope threshold too strict | Low correct-answer rate and refusal appropriateness | See diagnosis report | ≥ 10% |

This real-model evaluation also located and fixed the following defects (detail in
`reports/llm/ACCEPTANCE-CHECK-LLM.md`):

| Defect | Symptom | Fix |
|---|---|---|
| Multi-turn labels lacked cross-language fallback | English items had empty gold, so correct retrieval scored 0 | Fall back to the other language's anchor, as single-turn already did |
| Turn gating misclassification | Standalone new-topic questions were treated as follow-ups and replaced, answering the wrong topic | Gate only on anaphora and topic-less follow-ups |
| Rewriting by concatenation | Produced malformed compound questions and low compliance | LLM conversational rewriting with strict retry and deterministic fallback |
| Wrong generation input | With topic-less follow-ups the model answered off-topic | A/B testing confirmed generation must use the rewritten question |

## 6. Limitations and improvement paths

| Limitation | Impact | Improvement path |
|---|---|---|
| Compliance slightly below target | About half of non-compliant items are "should have answered but refused" | Relax the grounding threshold; strengthen citation-format instructions in the prompt |
| Cost uses example unit prices | Cost conclusion is not yet valid | Replace with the provider's current prices and recompute |
| Embeddings are a lightweight int8 model | Caps retrieval quality | Move to bge-m3 and re-ingest |
| Self-built corpus, rendered scans | Distribution differs from real material | Re-test with real documents and scans |
| Reranking still times out on some requests | Some requests do not use the reranked order | Reduce candidate count or raise the CPU budget |

## 8. Reproduction steps

```bash
uv sync --extra ocr && uv add tokenizers huggingface_hub
# 1. Ingest (corpus → OCR → chunking → ONNX embeddings)
uv run python scripts/ingest.py --config configs/llm_c3_hybrid_rerank.yaml --rebuild-corpus
# 2. Build the evaluation set
uv run python scripts/eval.py --rebuild-dataset --eval-dir data/eval_onnx
# 3. Three-config evaluation + comparison report
uv run python scripts/eval.py \
  --configs configs/llm_c1_vector.yaml configs/llm_c2_hybrid.yaml configs/llm_c3_hybrid_rerank.yaml \
  --eval-dir data/eval_onnx --report-dir reports/llm
# 4. Operations report / load test / diagnosis
uv run python scripts/report.py --config-version llm_c3_hybrid_rerank --report-dir reports/llm
uv run python scripts/loadtest.py --concurrency 5 --requests 200
uv run python scripts/diagnose.py
# 5. Generate deliverables
uv run python scripts/gen_log_docs.py
uv run python scripts/gen_eval_report.py --report-dir reports/llm --out reports/EVALUATION-REPORT.md
```
